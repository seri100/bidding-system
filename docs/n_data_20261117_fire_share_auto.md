# 배점한도 소방공사 자동정리 적용 기록

2026-11-17 Pi `/home/pi/n_data`에 적용했다. 기존 배점한도 감지 함수에 짧은 로컬 대기등록만 추가하고, 문서·업체조회·엑셀 저장은 독립 systemd 작업으로 분리했다. 기존 알림톡 발송·캘린더 동기화 조건은 수정하지 않았다.

## 적용 파일

- `fire_share_auto.py`: 지역·조건·공종비율 추출, 협회 페이지/상세 조회, 엑셀/원문 저장, 대기·재시도·중복 관리.
- `g2b_score_cap.py`: `FIRE_SHARE_QUEUE_V1` 블록으로 기존 감지 결과를 대기목록에 기록.
- `fire-share-auto.service`, `fire-share-auto.timer`: 5분 주기, 재부팅 후 시작, 독립 저우선순위 실행.
- `test_fire_share_auto.py`: 오류·차수·변경·중복·원문식별·NAS 장애·잠금·업체조회 재시도 시험 27개.

## 저장과 조회

출력은 `X:\VOL1\bid\소방분담\지역\공고번호-차수\`이다. 공고별 엑셀·검토정보·원문을 저장하며 기존 지역별 일괄 파일을 덮어쓰지 않는다.

업체목록은 협회 공개 회원사 조회의 일반(기계)·일반(전기)만 포함한다. 지역 전체 등록업체 목록을 보장하지 않는다. 등록일은 최초면허취득일이며 주소 전입일과 다르다. 마지막 성공 조회는 새 공고에서 24시간까지 재사용하고 이후 다시 조회한다. 실패 시 이전 성공 목록에 조회시각과 실패 상태를 표시하며 완료 처리하지 않는다.

- 실제 감지 함수 호출로 8건 대기등록, 실제 협회 조회와 자동 파일생성 8건 완료.

- 동시실행: 기존 작업이 실행 중이면 두 번째 작업이 SKIP 처리.

## 운영 점검

```bash
systemctl list-timers fire-share-auto.timer --no-pager
journalctl -u fire-share-auto.service -n 40 --no-pager
cat /home/pi/n_data/state/fire_share_auto/status.json
```

설치 전 백업: `/home/pi/n_data/backups/fire_share_auto_20261117_162148/`. NAS `_자동화/설치정보.json`에 적용파일 해시와 백업경로를 기록했으며, `_자동화/현재코드`에 최종 코드를 보관했다.

새 공고는 기존 수집 주기에 감지된 후 다음 5분 작업에서 처리한다. 업체조회·저장 소요시간이 추가되며 장애·누락된 원문은 상태를 기록하고 다음 실행에서 재시도한다.

최종 코드 버전: 1.0.2. 같은 공고의 여러 첨부에서 내용이 충분한 원문을 우선하고, 완전한 원문 사이 조건·비율이 상이하면 확인 필요로 표시한다. 읽을 수 없는 추가문서는 유효한 원문 처리를 막지 않으며 discovery_pending에 기록해 재검사한다. 최종 코드로 8건 저장 완료 후 동일 자료 8건 건너뛰기를 확인했다.
