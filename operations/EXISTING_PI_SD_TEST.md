# 기존 Pi의 시험용 SD 부팅·원복 절차

기록일: 2026-11-12, 한국시간. 사용자가 기존 Pi에서 안전조치 후 복구 시험을 하도록 요청했다. **현재 상태: 시험 이미지와 D: 기록·전체 읽기 검증 완료. 27개 활성 timer와 cron의 새 작업을 일시 중지하고 최종 상태 백업·복원 검증 후 안전 종료 명령을 완료했다. 시험 카드 교체를 기다린다. 실물 부팅·원복 시험은 아직 실행하지 않았다.**

## 현재 장치 구성

| 장치 | 용도 | 보호 방법 |
|---|---|---|
| Raspberry Pi 4 Model B Rev 1.2 | 현재 운영 본체 | 시험 후 같은 본체로 원복 |
| Pi 내부 SD 약 16GB | `/boot`, `/` 운영체제 | 원본을 별도 보관하고 시험용 카드를 사용 |
| Pi USB 저장장치 약 64GB | `/home`, `/var` | 전체 백업 후 시험 부팅 때 물리적으로 분리 |
| NAS CIFS | 운영 원자료·첨부·발송 상태 | 시험 OS에서 자동 연결/쓰기를 차단 |
| PC D: 32GB 카드 | 사용자가 시험용으로 사용하도록 승인 | 기존 파일 암호화 백업·복원 검증 후 시험 이미지 기록 |

SD카드만 복사하면 `/home`과 `/var`가 빠진다. 반대로 시험용 SD가 기존 fstab을 그대로 사용하면 원본 USB를 마운트해 운영 자료에 쓸 수 있다. 따라서 시험 카드에는 필요한 `/home`·`/var`를 별도로 복원하고, 원본 USB·NAS 연결은 사용하지 않는 구성이 필요하다.

## 1. 운영을 유지하며 준비

- 시험용 카드를 PC 카드리더기에 연결하고 드라이브·실제 용량·기존 내용·대상을 확인한다.
- 새 카드에 기존 내용이 있으면 먼저 비공개 암호화 백업을 만든다.
- 현재 활성/비활성 timer, cron, 실행 중 service, 부팅 장치 구성을 기록한다.
- 코드·인증정보·수신자·SQLite·발송 이력의 최신 암호화 백업을 만들고 검증한다.
- 이 단계의 온라인 파일 백업을 전체 SD 이미지나 완전히 같은 시점의 전체 시스템 백업으로 표시하지 않는다.

사용자가 D: 32GB 카드 사용으로 결정을 변경했다. 디스크 번호 2, USB, 모델 `FNK TECH USB CARD READER`, 실제 용량 31,268,536,320바이트를 대조한다. 카드 기록과 전체 읽기 검증이 끝날 때까지 Pi 운영을 유지한다.

## 2. 시험 카드가 준비되면 작업을 잠시 중지

- 운영 중단 시각을 기록하고 실행 중 수집·발송이 끝나는 것을 확인한다.
- 기록한 관련 timer와 cron을 일시 중지해 새 작업 시작을 막는다. 진행 중 발송을 무작정 강제 종료하지 않는다.
- `/home`, `/var`, 부팅/설정, NAS 중복 발송 방지·대기 상태의 최종 백업을 추가로 만든다. SQLite는 backup API로 복제한다.
- 중단 동안의 누락 방지를 위해 기존 pending window와 중단 시작 시각 중 더 이른 값을 유지하는 재수집 기준을 준비한다.
- 최종 백업을 복원·검증한 뒤 안전 종료한다.

서비스 중단은 아직 실행하지 않았다. 실제 대상과 전체 백업이 갖춰진 후 이 단계를 수행한다.

## 3. 원본 SD 전체 이미지가 필요한 경우

1. Pi가 종료된 뒤 전원을 분리한다.
2. 운영 SD를 빼고 PC 카드리더기에 연결한다. Windows의 포맷 안내가 나와도 포맷하지 않는다.
3. 장치 용량과 부팅 디스크 식별값을 대조한 뒤, 원본 SD 전체를 **읽기 전용으로** 이미지 백업한다.
4. 전체 이미지의 암호화·해시 검증을 마치고 원본 SD는 운영 원본으로 구분해 보관한다.

기존 원본 SD의 덮어쓰기로 시험하지 않는다. 현재는 원본이 Pi에 들어 있으므로 이 오프라인 전체 이미지 백업도 아직 생성되지 않았다.

## 4. 시험용 SD 구성

- 별도 시험용 카드의 대상을 다시 확인한 후 기록한다.
- 동일 환경 복원 시험은 원본 OS 이미지와 최종 `/home`·`/var` 백업을 기준으로 구성한다.
- 시험용 fstab에서 운영 USB와 NAS 자동 마운트를 제거/차단한다. 이 변경은 시험 이미지에만 적용한다.
- 시험 OS의 자동 수집·발송 timer와 cron을 비활성화하고, 외부 문자/카카오/Calendar 및 NAS 쓰기를 차단한 뒤 부팅한다.
- 원본 USB 저장장치는 분리한 상태로 두고, 시험용 SD만 Pi에 넣는다.

이번 시험은 원본 SD 전체 이미지 대신 인증된 전체 파일시스템 백업과 읽기 전용으로 추출한 부팅 영역을 사용했다. WSL의 일반 파일에 `mke2fs -d`로 파일시스템을 작성했으며 실제 디스크 연결이나 마운트를 하지 않았다. 파일시스템 검사와 격리 표식 확인은 통과했다. 카드의 물리 부팅은 별도 검증이 필요하다.

## 5. 기존 Pi 본체에서 시험

- PC에서 SSH로 접근해 부팅 장치·마운트·모델·OS·Python 버전을 확인한다.
- 원본 USB/NAS에 연결되지 않았고 자동 발송이 차단됐는지 먼저 확인한다.
- 코드·의존성·SQLite·인증파일·발송 이력과 프로그램의 안전한 시험 실행 결과를 확인한다.
- 실발송이나 운영 Calendar 갱신 없이 복원 결과를 기록한다.
- 실패해도 시험 카드를 수정하는 데 그치며 원본 SD/USB를 덮어쓰지 않는다.

## 6. 원래 운영으로 복귀

1. 시험 OS를 종료하고 전원을 분리한다.
2. 운영 원본 SD와 원본 USB 저장장치를 원래대로 연결한다.
3. 전원을 켜고 SSH·원래 `/home`·`/var`·NAS 마운트를 확인한다.
4. 작업 전 기록과 비교해 필요한 timer/cron만 원래 상태로 돌린다. 모든 timer를 일괄 활성화하지 않는다.
5. 중단 구간 재수집과 정상 종료, 결과 파일, 중복 발송 방지 상태를 확인한다.
6. 시험/원복 결과와 커밋을 매뉴얼에 추가한다.

## 운영 일시 중지와 복귀 도구

`operations/tools/pi_maintenance.py`는 활성 timer와 cron 상태를 기록하고 새 작업 시작만 막는다. 진행 중 작업 종료를 기다리며 강제로 발송을 종료하지 않는다. 30분 자동 원복 timer를 먼저 만들어 종료 이전 연결 장애에 대비한다. 수집 누락 방지 시작 시각을 기존 대기 구간과 비교해 더 이른 값으로 보존한다. 최종 상태 백업 후 안전 종료하며 원래 SD/USB로 복귀한 뒤 기록에 있는 timer·cron만 복구한다. 일시 중지·종료는 아직 실행하지 않았다.

최종 애플리케이션 백업은 확장자 없는 `state`/`send_history` 파일도 포함한다. SQLite는 backup API로 복제하므로 임시 WAL/SHM/journal을 별도 원본처럼 덮어쓰지 않는다. `apply_trial_snapshot.py`는 시험 표식과 SD 로컬 마운트, 격리 서비스, 서비스 마스크를 확인한 뒤 인증된 백업의 `/home/pi`와 로컬 `/mnt/vol1` 자료만 적용한다. 부팅 설정·systemd·cron은 덮어쓰지 않아 시험 격리를 유지한다. 이 적용도 실제 수행 후 결과를 기록한다.

GitHub 준비 코드: `64d850a78a8e01009a185bfe4393680232098de4`. 해당 커밋의 Operations recovery checks는 통과했다. 이는 카드의 실제 부팅 성공을 의미하지 않는다.

## 시험 이미지 재작성 명령

다음은 이번 비공개 파일을 기준으로 한 WSL 예시다. 먼저 `openssl`, GNU `tar`(ACL/xattr 지원), `rsync`, `mke2fs`, `e2fsck`, `debugfs`, Python 3를 확인한다. 아래 작업은 일반 디렉터리와 이미지 파일만 다룬다. 물리 SD 기록은 마지막 Windows 도구에서만 수행한다. 기존 작업 폴더를 재사용하지 않는다.

```bash
cd /mnt/c/Users/main/n_data_commit_20261112/operations/tools
BACKUP_DIR=/mnt/c/Users/main/n_data-recovery-private/pre-sd-test-20261112/pi-filesystems
RECOVERY_KEY=/mnt/e/n_data-recovery-key/backup.key
TRIAL_WORK=/home/main/n_data-trial-rebuild-20261112
sudo python3 restore_fs_archive.py --archive "$BACKUP_DIR/root-boot-precopy-20261112_142158.tar.gz.enc" --key "$RECOVERY_KEY" --workspace "$TRIAL_WORK" --name root
sudo python3 restore_fs_archive.py --archive "$BACKUP_DIR/home-var-precopy-20261112_135526.tar.gz.enc" --key "$RECOVERY_KEY" --workspace "$TRIAL_WORK" --name home-var
sudo python3 build_trial_image.py --workspace "$TRIAL_WORK" --boot-prefix "$BACKUP_DIR/boot-prefix-20261112_145258.bin.gz.enc" --key "$RECOVERY_KEY"
```

각 `.enc`의 `.hmac`도 같은 폴더에 있어야 하며, boot-prefix의 `.layout.json`도 필요하다. 결과 `trial.img`와 `trial.img.ready.json`을 접근 제한된 Windows 비공개 폴더로 함께 복사한다. 이미지에는 인증정보가 포함되므로 GitHub에 올리지 않는다.

Windows 관리자 PowerShell에서는 `Get-Disk`와 `Get-Partition`으로 대상을 다시 확인한 뒤 `write_trial_sd.ps1`의 필수 인수를 지정한다. 이번 대상 값은 디스크 2, 드라이브 D, USB 모델 `FNK TECH USB CARD READER`, 용량 31,268,536,320바이트였다. 다음 시험에서 이 번호가 같다고 가정하지 않는다. 원래 카드 파일의 인증된 백업과 manifest, 키를 함께 지정해야 도구가 기록을 시작한다. `.card-verified.json`의 `verified=true`와 원본 이미지 SHA256 일치가 완료 기준이다. 기록 중 Windows 포맷 안내가 나타나도 포맷하지 않는다.
