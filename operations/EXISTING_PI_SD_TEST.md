# 기존 Pi의 시험용 SD 부팅·원복 절차

기록일: 2026-11-12, 한국시간. 사용자가 기존 Pi에서 안전조치 후 복구 시험을 하도록 요청했다. **현재 상태는 준비 단계이며 운영 중단·종료·SD 기록·실물 부팅 시험은 아직 실행하지 않았다.**

## 현재 장치 구성

| 장치 | 용도 | 보호 방법 |
|---|---|---|
| Raspberry Pi 4 Model B Rev 1.2 | 현재 운영 본체 | 시험 후 같은 본체로 원복 |
| Pi 내부 SD 약 16GB | `/boot`, `/` 운영체제 | 원본을 별도 보관하고 시험용 카드를 사용 |
| Pi USB 저장장치 약 64GB | `/home`, `/var` | 전체 백업 후 시험 부팅 때 물리적으로 분리 |
| NAS CIFS | 운영 원자료·첨부·발송 상태 | 시험 OS에서 자동 연결/쓰기를 차단 |
| PC에 현재 연결된 D: 32GB 카드 | 사용자가 시험용이 아니라고 확인 | 시험 대상에서 제외 |

SD카드만 복사하면 `/home`과 `/var`가 빠진다. 반대로 시험용 SD가 기존 fstab을 그대로 사용하면 원본 USB를 마운트해 운영 자료에 쓸 수 있다. 따라서 시험 카드에는 필요한 `/home`·`/var`를 별도로 복원하고, 원본 USB·NAS 연결은 사용하지 않는 구성이 필요하다.

## 1. 운영을 유지하며 준비

- 시험용 카드를 PC 카드리더기에 연결하고 드라이브·실제 용량·기존 내용·대상을 확인한다.
- 새 카드에 기존 내용이 있으면 먼저 비공개 암호화 백업을 만든다.
- 현재 활성/비활성 timer, cron, 실행 중 service, 부팅 장치 구성을 기록한다.
- 코드·인증정보·수신자·SQLite·발송 이력의 최신 암호화 백업을 만들고 검증한다.
- 이 단계의 온라인 파일 백업을 전체 SD 이미지나 완전히 같은 시점의 전체 시스템 백업으로 표시하지 않는다.

현재 사용자는 다른 시험용 카드를 준비하기로 했다. 그 카드가 확인되기 전에는 운영을 중단하지 않는다.

## 2. 시험 카드가 준비되면 작업을 잠시 중지

- 운영 중단 시각을 기록하고 실행 중 수집·발송이 끝나는 것을 확인한다.
- 기록한 관련 timer와 cron을 일시 중지해 새 작업 시작을 막는다. 진행 중 발송을 무작정 강제 종료하지 않는다.
- `/home`, `/var`, 부팅/설정, NAS 중복 발송 방지·대기 상태의 최종 백업을 추가로 만든다. SQLite는 backup API로 복제한다.
- 중단 동안의 누락 방지를 위해 기존 pending window와 중단 시작 시각 중 더 이른 값을 유지하는 재수집 기준을 준비한다.
- 최종 백업을 복원·검증한 뒤 안전 종료한다.

서비스 중단은 아직 실행하지 않았다. 실제 대상과 전체 백업이 갖춰진 후 이 단계를 수행한다.

## 3. 원본 SD를 읽기 전용으로 백업

1. Pi가 종료된 뒤 전원을 분리한다.
2. 운영 SD를 빼고 PC 카드리더기에 연결한다. Windows의 포맷 안내가 나와도 포맷하지 않는다.
3. 장치 용량과 부팅 디스크 식별값을 대조한 뒤, 원본 SD 전체를 **읽기 전용으로** 이미지 백업한다.
4. 전체 이미지의 암호화·해시 검증을 마치고 원본 SD는 운영 원본으로 구분해 보관한다.

기존 원본 SD의 덮어쓰기로 시험하지 않는다. 현재는 원본이 Pi에 들어 있으므로 이 오프라인 전체 이미지 백업도 아직 생성되지 않았다.

## 4. 시험용 SD 구성

- 별도 시험용 카드의 대상을 다시 확인한 후 기록한다.
- 동일 환경 복원 시험은 원본 OS 이미지와 최종 `/home`·`/var` 백업을 기준으로 구성한다.
- 시험용 fstab에서 운영 USB와 NAS 자동 마운트를 제거/차단한다. 이 변경은 시험 이미지에만 적용한다.
- 시험 OS의 자동 수집·발송 timer와 cron을 비활성화하고, 외부 문자/카카오/Calendar 및 NAS 쓰기를 차단한 뒤 부팅한다.
- 원본 USB 저장장치는 분리한 상태로 두고, 시험용 SD만 Pi에 넣는다.

해당 시험 이미지의 수정·기록·차단 검증은 아직 수행하지 않았다. 새 카드가 확인된 뒤 실제 이미지와 장치를 기준으로 검증한다.

## 5. 기존 Pi 본체에서 시험

- PC에서 SSH로 접근해 부팅 장치·마운트·모델·OS·Python 버전을 확인한다.
- 원본 USB/NAS에 연결되지 않았고 자동 발송이 차단됐는지 먼저 확인한다.
- 코드·의존성·SQLite·인증파일·발송 이력과 프로그램의 안전한 시험 실행 결과를 확인한다.
- 실발송이나 운영 Calendar 갱신 없이 복원 결과를 기록한다.
- 실패해도 시험 카드를 수정하는 데 그치며 원본 SD/USB를 덮어쓰지 않는다.

## 6. 원래 운영으로 복귀

1. 시험 OS를 종료하고 전원을 분리한다.
2. 운영 원본 SD와 원본 USB 저장장치를 원래대로 연결한다.
3. 전원을 켜고 SSH·원래 `/home`·`/var`·NAS 마운트를 확인한다.
4. 작업 전 기록과 비교해 필요한 timer/cron만 원래 상태로 돌린다. 모든 timer를 일괄 활성화하지 않는다.
5. 중단 구간 재수집과 정상 종료, 결과 파일, 중복 발송 방지 상태를 확인한다.
6. 시험/원복 결과와 커밋을 매뉴얼에 추가한다.

## 사용자가 다음에 할 일

**별도의 시험용 SD카드를 PC 카드리더기에 연결하고 연결됐다고 알려준다.** 아직 Pi를 종료하거나 기존 SD/USB를 빼지 않는다. 다음 단계는 연결된 시험 카드를 확인한 뒤 진행한다.
