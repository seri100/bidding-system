## 복원 전에 해결할 항목

1. **사라진 실행 경로:** `/home/pi/road`, `/home/pi/seri_Alarm_Server10`. 예약설정에서 참조하지만 현재 경로가 없어 코드 확보가 안 됐다. 삭제된 작업인지, 다른 경로로 이관했는지 추가 확인이 필요하다. 해당 기능을 복원 완료로 간주하지 않는다.
2. **구형 파일의 원래 문법 오류:** `n_data/251210-main_send.py`, `n_data/main_send_fixed.py`, `seri_Alarm_Server2/main_crawling_251225.py`, `seri_Alarm_Server2/main_crawling_251226.py`. 암호화 원본에는 포함했지만 공개 실행 소스에서는 제외했다. 현재 실행 진입점과 동일한 파일이라는 의미는 아니다.
3. **비활성 healthcheck 설정:** `/etc/default/main_send_healthcheck`를 확보하지 못했다. 사용을 재개할 경우 설정을 재작성해야 한다.
4. **Windows 자동 보관 실패:** 11월 11·12일 기록은 `archive-bids.mjs` 5행 실패다. 해당 행은 X 드라이브 접근 검사다. 점검 당시 X 드라이브는 접근 가능했고, 작업은 Interactive/사용자 main으로 설정돼 있었다. 원인 후보는 실행 당시 ipDISK 드라이브 준비 상태이며, 실행 당시 상태를 직접 재현한 것은 아니다. 저장 정책을 변경하지 않았다.
5. **의존성 보안 점검:** 대시보드의 기존 lockfile로 `npm ci` 시 12건(중간 4·높음 8)의 취약점이 보고됐다. 설치·빌드·기능 시험은 통과했다. 이번 복구 정리에서 강제 업데이트는 하지 않았으며 별도 호환성 검증 후 수정해야 한다.
6. **외부 데이터/권한:** NAS 전체 raw·첨부·과거 로그, 외부 MongoDB 전체, Google Calendar 전체 내보내기, Cloudflare Secret 원문, 라우터·Windows 전체 환경 이미지는 이 코드/상태 스냅샷에 포함되지 않는다. Cloudflare Secret은 재발급 가능한 Google 권한을 준비해야 한다.
7. **전체 장치 복구 시험:** 새 SD카드/새 Windows PC에서 처음부터 설치·부팅·외부 연동하는 시험은 수행하지 않았다. 이번 staging 복원 성공을 전체 장치 복구 보증으로 해석하지 않는다.

## 운영 변경 관리의 현재 한계

Pi의 운영 폴더는 Git 작업 트리가 아니다. 현재 코드의 검토용 사본을 통합 저장소에 만들었으며, 공개 사본의 `REDACTED_*` 부분은 비공개 원본을 통해 복구한다. 운영 파일이 바뀌면 자동으로 GitHub에 올라가는 상태는 아니다. 변경 작업 때 백업·공개 가능한 소스 반영·시험·commit/push를 함께 진행한다.

현재 인증정보가 코드에 하드코딩된 곳을 모두 환경변수로 바꾸지는 않았다. 따라서 공개 저장소 단독 clone만으로 운영 환경이 완성되지 않으며, 암호화 원본/비공개 설정과 데이터 백업이 함께 있어야 한다.
