# 배점한도 소방공사 지역별 자동정리

나라장터 n_data에서 배점한도 소방공사를 감지하면 로컬 대기목록에 기록한다. 별도 systemd 작업이 5분마다 원문과 협회 업체목록을 정리한다. 저장 오류가 입찰 수집과 알림톡 발송을 중단시키지 않는다.

## 결과 위치

Windows: `X:\VOL1\bid\소방분담\지역\공고번호-차수\`
Pi: `/mnt/vol1/소방분담/지역/공고번호-차수/`

이 NAS는 `//192.168.0.250/bid`를 `/mnt/vol1`에 마운트하므로 `/mnt/vol1/bid/소방분담`이 아니다.

각 공고 폴더에 `공고번호-차수_소방분담.xlsx`, `검토정보.json`, `원문/`을 저장한다. 엑셀 시트는 공고검토, 분담비율, 원문근거, 업체목록, 조회현황이다. 기존 20261117 지역별 일괄 정리 파일을 덮어쓰지 않는다.

## 조건 추출과 업체조회

- 대상: 원문에 시공경험 배점한도와 경영상태 평가 문구가 있는 소방공사.
- 지역은 공사현장/조달청 주소가 아닌 참가자격·지역의무 조항에서 확인한다.
- 지역제한과 지역의무를 구분한다. 지역제한을 의무참여 0%로 표시하지 않는다.
- 기계·전기 공종의 관급 포함 추정금액 비율과 도급금액 비율을 구분한다. 적격심사 평가비율과 혼동하지 않는다.
- 공동·분담·혼합이행, 최소지분, 대표자 조건의 근거를 함께 저장한다. 혼합방식을 명시하지 않으면 허용으로 추정하지 않는다.
- 해석할 수 없는 항목은 `확인 필요`, 지역을 확인할 수 없으면 `_확인필요` 폴더에 정리한다.
- 협회 공개 회원사 조회에서 지역별 일반(기계), 일반(전기)를 각각 조회한다. 경기는 북·남을 모두 조회한다.
- 업체 검색건수와 페이지 수집건수를 대조하고 상세페이지의 상호·면허를 확인한다.
- 상호, 주소, 면허종류, 대표자, 전화번호, 최초면허취득일, 등록번호, 조회 출처를 저장한다.
- 등록일 열은 협회의 `최초면허취득일`이며 전입일을 증명하지 않는다.
- 0건은 회원사 조회 결과이며 해당 지역 전체 등록업체가 없다는 뜻이 아니다.

## 중복·변경·실패 처리

공고번호+차수가 식별키이다. 차수가 증가하면 별도 공고 폴더를 만든다. 같은 차수의 원문 파일 내용 변경도 감지해 갱신한다. 성공한 동일 자료는 반복 저장하지 않는다.

업체목록은 마지막 성공 조회 후 24시간까지 새 공고에서 재사용한다. 이후 새 공고가 들어오면 다시 조회한다. 조회 실패 시 마지막 성공 목록이 있으면 조회시각과 재시도 상태를 표시해 저장하고 재시도한다. 이전 목록이 없으면 실패를 0건으로 표시하지 않는다.

대기목록과 실행상태는 Pi 로컬 `/home/pi/n_data/state/fire_share_auto`에 보관한다. NAS 미연결, 업체조회 실패, Excel 파일 잠금 등은 대기목록을 삭제하지 않고 다음 실행에서 재시도한다. 기존 파일은 임시파일 저장·검증 후 원자적으로 교체한다. 성공한 자료만 완료 처리한다.

보조 발견 작업은 최근 30일의 n_data 첨부파일 보관소를 검사한다. 실행마다 최대 80개의 새/변경 원문을 검사하여 재시작 시 미처리 공고도 찾아낸다. 원문을 읽지 못하면 다음 실행에서 재시도한다. 이 기능은 n_data의 첨부파일 수집 범위를 전제로 하며 다른 기관 수집기의 별도 저장소까지 자동 검색하지 않는다.

## 점검

```bash
systemctl status fire-share-auto.timer --no-pager
systemctl list-timers fire-share-auto.timer --no-pager
journalctl -u fire-share-auto.service -n 40 --no-pager
cat /home/pi/n_data/state/fire_share_auto/status.json
```

NAS에서 `소방분담/자동정리_실행상태.json`으로 마지막 실행과 재시도 목록을 확인할 수 있다. `discovery_pending`에는 읽지 못한 원문 파일과 오류가 표시되며 다음 실행에서 재검사한다. `review_needed`는 자동 추출로 확정할 수 없는 원문 항목이 있다는 뜻이고 `retry`는 업체조회 또는 저장 재시도가 필요하다는 뜻이다.

개별 공고 재처리:

```bash
cd /home/pi/n_data
python3 fire_share_auto.py --queue-only --only R26BK01834905-000 --force
```

자동 작업을 정지한 뒤 수동 재처리할 경우 `sudo systemctl stop fire-share-auto.timer`를 먼저 실행하고, 확인 후 `sudo systemctl start fire-share-auto.timer`로 복구한다. 기본 프로세스 잠금이 중복 실행을 막는다.

## 설치·시험·복원

```bash
python3 install_fire_share_auto.py
cd /home/pi/n_data
python3 -m unittest test_fire_share_auto -q
sudo systemctl enable --now fire-share-auto.timer
sudo systemctl start --no-block fire-share-auto.service
```

설치 전 `g2b_score_cap.py`와 기존 자동화 파일/서비스는 `/home/pi/n_data/backups/fire_share_auto_날짜시각/`에 백업한다. 같은 내용은 NAS의 `소방분담/_자동화/변경전백업_날짜시각/`에 보관한다. 설치 패키지와 `설치정보.json`도 `_자동화`에 저장한다.

복원은 타이머를 중지·비활성화하고, `설치정보.json`의 backup 경로에서 `g2b_score_cap.py`를 원복한 뒤 구문검사를 한다. 운영 중 다른 변경이 추가됐다면 백업 전체 원복 대신 `FIRE_SHARE_QUEUE_V1` 추가 블록만 제거한다. 이 기능은 다른 알림톡·캘린더 설정을 바꾸지 않는다.
