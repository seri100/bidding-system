# n_data 작업을 이어갈 때

1. README, `docs/incidents/2026-10-23-joint-region.md`, `manifest.json`, 후속 Issue https://github.com/seri100/bidding-system/issues/1 을 먼저 읽는다. 문서의 적용 시각은 과거 관측값이다. 현재 운영 상태는 다시 읽기 전용으로 확인한다.
2. GitHub 동기화나 PR 병합은 라즈베리파이 자동 배포를 뜻하지 않는다. 운영 변경은 그때의 사용자 요청 범위에서 별도로 진행한다.
3. `jntcontrctDutyRgnNm1~3`는 공동도급지역, 참가가능지역은 별도 조건이다. 현장·기관 지역으로 공동도급지역을 추정하지 않는다. 공고별 지역 하드코딩을 추가하지 않는다.
4. 실제 제목은 검색 결과 td 안의 `label[id$='_bizNm']`이다. 숨겨진 검색 폼과 공지 팝업을 구분한다. 공고번호·차수가 일치하지 않으면 보완 성공으로 처리하지 않는다.
5. 검증된 환경은 Python 3.7 + Selenium + 시스템 Chromium/ChromeDriver다. 기존 Node 18/Node 22 호환 문제를 해결책으로 반복하지 않는다. 환경 교체는 별도 계획으로 다룬다.
6. 읽기 전용 실조회 → 발송 차단 검증 → 운영 원본 해시 확인 → 같은 서비스 flock 잠금 → 백업·적용·사후 확인 순서를 사용한다. 중복가드 삭제나 수동 재발송은 명시적으로 요청받았을 때만 한다.
7. 인증키, 전화번호, 수신자 JSON, SSH 키·접속 주소, 브라우저 프로필, 운영 로그/DB/전체 ZIP은 공개 저장소에 올리지 않는다. 전체 기존 소스가 필요하면 사용자 보관 원본을 별도 작업 경로에 가져온다.
8. 시험 프로세스는 세션/프로세스 그룹 단위로 제한하고 종료한다. 셸 timeout으로 부모만 종료해 ChromeDriver를 남기지 않는다.
9. 성공한 단계와 실패한 단계를 구분해서 기록한다. 도구 실행이 끝난 뒤 백그라운드 작업이 계속된다고 표현하지 않는다. 실제 발송 확인과 발송 차단 검증을 구별한다.
